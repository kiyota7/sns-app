# (仮称)タイムラインSNS

X(旧Twitter)風の、投稿・タイムライン・コメント・いいね・フォローができる学習目的のSNS
Webアプリケーション。受講生・個人など複数の利用者が使うことを想定し、いいね・コメントは
投稿者本人だけでなく第三者からも行える設計としている(詳細は[要件定義書](要件定義書.md)参照)。

現在、F-01〜F-15(認証・投稿の作成/編集/削除・全体/フォロー中タイムライン・コメント・いいね・
フォロー・プロフィール表示/編集・ユーザー検索)をすべて実装済み。AWSデプロイは次フェーズで進める。

## データモデル概要

詳細・ER図は[データベース設計書](docs/データベース設計書.md)を参照。

- `users`: 利用者(ユーザー名・メールアドレス・パスワード・自己紹介)
- `posts`: 投稿(本文・画像URL(任意))
- `comments`: 投稿へのコメント
- `likes`: 投稿へのいいね(利用者×投稿でUNIQUE)
- `follows`: 利用者間のフォロー関係(自己参照の多対多)

いいね数・コメント数は`posts`にカウンタを持たず、`likes`/`comments`をその都度`COUNT`集計して
算出する方針としている。

## バックエンド(会員登録・ログイン・ログアウト)

Java(Spring Boot) + MyBatis + SQLite + JWT認証(アクセストークン+リフレッシュトークン方式)で
実装している。詳細は
[技術スタック](docs/技術スタック.md)・[ローカル開発環境セットアップ](docs/ローカル開発環境セットアップ.md)を参照。

```bash
cd backend
mvn spring-boot:run
# http://localhost:8080/api/auth/register 等にPOSTして動作確認できる
```

エンドポイント: `POST /api/auth/register`・`POST /api/auth/login`・`POST /api/auth/refresh`・
`POST /api/auth/logout`・`GET /api/auth/me`(認証必須)。アクセストークンは短命(15分)、
リフレッシュトークンは長命(7日)で、`/api/auth/refresh`を呼ぶたびにリフレッシュトークンも
ローテーションされる。ログアウト・リフレッシュで使用済みになったトークンはjti(トークンID)を
blacklistに登録することで、以降使えなくする。

## バックエンド(投稿の作成・編集・削除・タイムライン・コメント・いいね)

`POST /api/posts`(`multipart/form-data`。本文+画像は任意)・`GET /api/posts`(全体タイムライン、
新しい順)・`GET /api/posts/{id}`・`PUT /api/posts/{id}`・`DELETE /api/posts/{id}`(編集・削除は
本人の投稿のみ、他人の投稿への操作は403)。添付画像はS3等を使わず`backend/uploads/`にローカル保存し、
`/uploads/**`で静的配信する(認証不要でアクセス可能)。

- `POST /api/posts/{id}/likes`: いいねのトグル(登録済みなら解除)。`{liked, likeCount}`を返す
- `GET /api/posts/{postId}/comments`・`POST /api/posts/{postId}/comments`: コメント一覧(新しい順)・投稿
- 投稿削除時は紐づくコメント・いいねも削除する

いいね数・コメント数・自分がいいね済みかは、投稿一覧取得時に投稿ごとの追加クエリを発行するのではなく、
`posts`取得と同じSQL内の相関サブクエリとして1回で集計している(N+1回避。詳細は
`backend/src/main/resources/mapper/PostMapper.xml`の`selectWithAuthor`を参照)。

## バックエンド(プロフィール・フォロー)

- `GET /api/users/{id}`: プロフィール取得(ユーザー名・自己紹介・フォロー数/フォロワー数・
  自分がフォロー済みか)。フォロー数等も`PostMapper`と同じ考え方で相関サブクエリとして
  1回のSQLで集計している(`UserMapper.xml`の`findProfileById`)
- `GET /api/users/{id}/posts`: 指定ユーザーの投稿一覧(新しい順)
- `PUT /api/users/me`: 自分のユーザー名・自己紹介を更新(ユーザー名は他ユーザーと重複不可、
  自分自身の現在の値との比較は除外)
- `POST /api/users/{id}/follow`: フォローのトグル(登録済みなら解除)。自分自身のフォローは400
- `GET /api/users?query=`: ユーザー名の部分一致検索(自分自身は除外)。空クエリなら自分以外の全ユーザーを返す

`GET /api/posts`は`?scope=following`を指定すると、フォロー中の利用者の投稿だけを返す
(`PostMapper`に`follows`とのJOINを追加しただけで、他の一覧取得と同じくN+1なしで実現している)。

## フロントエンド(新規登録・ログイン・タイムライン・投稿詳細・プロフィール・検索)

Vue.js(Vite)で実装している。ログイン・新規登録に成功するとアクセストークン・リフレッシュ
トークン・ユーザー情報を`localStorage`に保存し、タイムライン画面(`/timeline`)に遷移する。

`src/lib/api.js`の`authFetch()`が認証付きAPIリクエストの共通処理を担う。リクエストには
`Authorization: Bearer <アクセストークン>`ヘッダーを自動付与し、レスポンスが401(アクセス
トークン失効)の場合は`/api/auth/refresh`を1回呼んでトークンを再発行し、リクエストを
リトライする。それでも失敗する場合(リフレッシュトークンも失効)はログイン画面へ戻す。

`/timeline`画面では投稿の作成(本文+画像添付)・自分の投稿の編集(インライン)・削除・
いいねができ、「全体」「フォロー中」タブで投稿一覧の対象を切り替えられる(画面遷移せず
一覧内容のみ切り替わる)。投稿カードのコメント数をクリックすると投稿詳細画面(`/posts/:id`)に
遷移し、コメント一覧の閲覧・コメント投稿ができる。投稿カードは`src/components/PostCard.vue`
としてタイムライン・投稿詳細・プロフィールの3画面で共通利用している。

投稿者名やヘッダーの自分のユーザー名をクリックするとプロフィール画面(`/users/:id`)に遷移する。
自分のプロフィールでは「プロフィールを編集」からユーザー名・自己紹介を変更でき、他人の
プロフィールでは「フォローする」/「フォロー解除」ボタンを表示する。ヘッダーの検索アイコンから
ユーザー検索画面(`/search`)に遷移し、ユーザー名で絞り込み・各結果からのフォローができる。

```bash
cd frontend
npm install
npm run dev
# http://localhost:5173 を開く(/api・/uploadsは自動的にバックエンド(8080)へプロキシされる)
```

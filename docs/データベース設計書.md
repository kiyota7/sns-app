# データベース設計書

[機能一覧](機能一覧.md)を満たすため、`users`(利用者)・`posts`(投稿)・`comments`(コメント)・
`likes`(いいね)・`follows`(フォロー関係)の5テーブルで設計する。DBMSは次フェーズ(技術選定)で
決定するため、ここでは論理設計(テーブル・カラム・関連)のみを示す。

## ER図

```
users                     posts                    comments
+----+----------+   1   N +----+---------+   1   N +----+---------+
| id | username |---------| id | user_id |---------| id | post_id |
+----+----------+         |    | body    |         |    | user_id |
     │  ▲                  |    | image_url|         |    | body    |
     │  │                  +----+---------+         +----+---------+
     │  │                        │  1
     │  │                        │
     │  │                        │ N
     │  │                     likes
     │  │               +----+---------+
     │  │               | id | post_id |
     │  │               |    | user_id |
     │  │               +----+---------+
     │  │                        ▲ N
     │  └────────────────────────┘ (userごとに複数のlikeを持つ)
     │
     │ N                followsは自己参照(users同士)
     ▼
follows
+----+-------------+-------------+
| id | follower_id | followed_id |
+----+-------------+-------------+
```

- `posts.user_id`・`comments.user_id`・`comments.post_id`・`likes.user_id`・`likes.post_id`は、
  それぞれ`users.id`・`posts.id`を参照する外部キー
- `follows`は`users`同士の多対多関係(自己参照)を表す中間テーブルで、`follower_id`(フォローする側)・
  `followed_id`(フォローされる側)の2つの外部キーを持つ

## テーブル定義

### users(利用者)

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | BIGINT | PK, AUTO_INCREMENT | 利用者ID |
| username | VARCHAR(50) | NOT NULL, UNIQUE | ユーザー名(表示名・検索対象) |
| email | VARCHAR(255) | NOT NULL, UNIQUE | メールアドレス(ログインID) |
| password_digest | VARCHAR(255) | NOT NULL | ハッシュ化されたパスワード |
| bio | VARCHAR(160) | NULL可 | 自己紹介文(プロフィール画面用) |
| created_at | DATETIME | NOT NULL | 登録日時 |
| updated_at | DATETIME | NOT NULL | 更新日時 |

### posts(投稿)

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | BIGINT | PK, AUTO_INCREMENT | 投稿ID |
| user_id | BIGINT | NOT NULL, FK → users.id | 投稿者 |
| body | TEXT | NOT NULL | 投稿本文 |
| image_url | VARCHAR(500) | NULL可 | 添付画像のURL(任意) |
| created_at | DATETIME | NOT NULL | 投稿日時 |
| updated_at | DATETIME | NOT NULL | 更新日時(編集機能F-05で使用) |

### comments(コメント)

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | BIGINT | PK, AUTO_INCREMENT | コメントID |
| post_id | BIGINT | NOT NULL, FK → posts.id | コメント対象の投稿 |
| user_id | BIGINT | NOT NULL, FK → users.id | コメント投稿者 |
| body | TEXT | NOT NULL | コメント本文 |
| created_at | DATETIME | NOT NULL | コメント日時 |

### likes(いいね)

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | BIGINT | PK, AUTO_INCREMENT | いいねID |
| post_id | BIGINT | NOT NULL, FK → posts.id | いいね対象の投稿 |
| user_id | BIGINT | NOT NULL, FK → users.id | いいねした利用者 |
| created_at | DATETIME | NOT NULL | いいね日時 |

`(post_id, user_id)`にUNIQUE制約を設け、同一利用者が同じ投稿に重複していいねできないようにする。

### follows(フォロー関係)

| カラム名 | 型 | 制約 | 説明 |
|---|---|---|---|
| id | BIGINT | PK, AUTO_INCREMENT | フォロー関係ID |
| follower_id | BIGINT | NOT NULL, FK → users.id | フォローする側の利用者 |
| followed_id | BIGINT | NOT NULL, FK → users.id | フォローされる側の利用者 |
| created_at | DATETIME | NOT NULL | フォロー開始日時 |

`(follower_id, followed_id)`にUNIQUE制約を設け、重複フォローを防ぐ。また、
`follower_id = followed_id`(自分自身のフォロー)はアプリケーション側のバリデーションで禁止する。

## 集計・取得クエリの考え方

- **いいね数・コメント数**: `posts`テーブル自体にカウンタカラムは持たせず、`likes`/`comments`を
  `post_id`で`GROUP BY`して`COUNT`する形で都度算出する
- **全体タイムライン(F-07)**: `posts`を`created_at`の降順で取得する
- **フォロー中タイムライン(F-08)**: `follows`で`follower_id = ログイン中のuser_id`の行から
  `followed_id`一覧を取得し、その`user_id`に該当する`posts`のみを`created_at`降順で取得する
  (`posts JOIN follows ON posts.user_id = follows.followed_id`という結合で実現できる)
- **フォロー数・フォロワー数(S-05)**: `follows`を`follower_id`(フォロー数)・`followed_id`
  (フォロワー数)それぞれで`COUNT`する
- **ユーザー検索(F-13)**: `users.username`に対する部分一致(`LIKE`等)検索

## 初期データについて

`users`・`posts`等の初期データ(seed)は、技術選定後の実装フェーズで、動作確認用の
サンプルアカウント・投稿として用意する想定。
